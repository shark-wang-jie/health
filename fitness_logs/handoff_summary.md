- 同日多段训练各计一次、各自稳定 `event_id`；同一次训练多设备读数放同一条目，不许重复计。
- 状态语义：未报告 ≠ 0 ≠ 休息；封账 ≠ 资料完整；有整段未记录饮食时，不得用部分摄入报缺口。

- 汇报口径：缺口是模型估算非实测；不因缺口大就夸做得好，也不拿封账掩盖未量化部分。

## 记录流程

1. 改 `daily/YYYY-MM/YYYY-MM-DD.json`（必要时同改 `handoff_summary.md`）；跨文件同一业务必须**一个原子 commit**。
2. `python3 fitness_logs/record_tools.py recalculate <json>` → `validate` → `report` → `jq empty`。
3. 提交走 gh api Git data API（网络不稳，`git clone/push` 会断）：`POST /git/blobs` → `POST /git/trees`（base_tree=head tree）→ `POST /git/commits` → `PATCH /git/refs/heads/main`（force:false），随后回读 main 比对 sha256。失败如实报告，不强推。
4. 每日约 22:00 更新本摘要，保持简洁、不堆历史详单。
